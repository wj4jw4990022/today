# 健康餐官網｜整合方式與決策紀錄

紀錄日期：2026-10-22（持續更新）
依據：「官網_健康餐與會員系統_開發需求」。以下是與負責人逐項討論後的決定；規則數字仍待主管批准，皆放在「健康餐設定」工作表。

## 已決定

### 試算表新增欄位（已建立，皆加在最右邊）
- 「預約」S 欄「單點原價」：預約時記下當下單點價，到期／取消結算用，之後調價不影響舊紀錄。
- 「預約」T 欄「取餐時間」：實際取餐或送達時間，處理未取餐、客訴用。
- 「會員」M 欄「條款同意時間」：留下同意條款的紀錄。
- 「會員」N 欄「Email已驗證時間」：有時間＝已驗證，空白＝未驗證。

### 會員身分與驗證
- 註冊／登入：LINE 登入。一個 LINE 帳號只能有一個會員。
- 不使用簡訊驗證。手機由會員自己填；「一支手機只能一個帳號」由系統檢查。
- 「手機已驗證」：店員在首次確認收款時核對手機後，在後台勾選。
- Email：必填，並用 6 位數驗證碼驗證（10 分鐘有效、輸錯 5 次作廢、同 Email 60 秒內只能要一次、每天最多 5 次；每個 LINE 帳號每天最多 5 次）。改 Email 需重新驗證。
- 一個 Email 只能註冊一個帳號；Gmail 的點號與 + 後綴視為同一信箱；可加免洗信箱黑名單。
- 寄信：先沿用 Apps Script 內建寄信（一般 Gmail 每天約 100 封上限），寄信獨立成一層；自訂網域確定後改用專門寄信服務（SPF／DKIM）。後台提供「手動標記 Email 已驗證」作為備案；系統記錄當日寄信數，接近上限時通知。

### LINE
- 已有 LINE 官方帳號，目前為「輕用量」（免費，每月主動推播 200 則）。
- LINE 登入 channel 須建在「與官方帳號 Messaging API channel 相同的 Provider」底下，識別碼才能對應推播。（待負責人確認 Provider 名稱）
- 之後會換自訂網域；LINE 登入需同時登記舊、新回呼網址。建議 11/13 上架前換好，避免會員重新登入。

### 錢包與退現金
- 錢包裡的錢分兩類：「可退現金」（儲值金、退款轉入的消費金）與「不可退」（推薦獎勵消費金，只能折抵消費）。
- 扣款順序：先扣「不可退」的獎勵消費金，再扣可退的錢。系統依紀錄時間順序重放計算「可退現金金額」，不需新增欄位（類型：儲值、退款轉入＝可退；推薦獎勵＝不可退；獎勵收回扣不可退；退現金只扣可退）。
- 退現金不收手續費。
- 人工調整（加值）預設視為「不可退」；若是更正儲值登錄錯誤，後台可勾選「可退」。（預設值，負責人如有異議再改）
- 會員中心顯示「錢包總餘額」與「可退現金金額」。
- 預付與儲值是否適用禮券規範，上線前請律師或消保官確認。

### 到期與取消的結算
- 結算用「實付金額」（已扣除推薦折扣）減去已吃餐的單點原價；例：12 餐 1,980 元、推薦折 100、吃 8 餐 LIGHT 雞胸（190）→ 1,880 − 1,520 = 360 元。
- 作廢的餐（沒來取餐、配送時不在）算已吃，扣單點原價；店家補償的餐不算已吃；配送改自取的餐算已吃。
- 整期升級另外付的差額不重複計算；結果小於 0 以 0 計。
- 單點原價用預約當下記錄的「單點原價」欄位，不受之後調價影響。

### 預約日期規則
- 不能預約當天，須在前一天 20:00（可在設定調整）前預約；只能預約本期「開始日～到期日」內；公休日（週三）與暫停期間不能預約；只有「使用中」的訂閱可預約。
- 一天可午、晚各一餐，同一時段只能一份。

### 暫停規則
- 起日只能選尚未鎖定的日期（20:00 前申請最早明天，20:00 後申請最早後天）；1～7 個日曆天（公休日也算）；到期日往後延相同天數。
- 暫停期間內已預約的餐自動取消，不扣餐數，並通知會員。
- 申請後不能取消、不能提前恢復（要改找店員）；每期只能一次；只有「使用中」且剩餘餐數大於 0 的訂閱可暫停。

### 配送點與免運門檻
- 「份數」＝預約的餐數（同會員訂 2 份算 2 份）；只算同一配送點、同一天、同一時段、狀態為「已預約」的；預約頁顯示「已有 N 份，滿 M 份才會配送」，不顯示是誰訂的。
- 距離邊界：剛好 2 公里算「2 公里內」（門檻 3）、剛好 5 公里算「2～5 公里」（門檻 5）、剛好 8 公里算「5～8 公里」（門檻 10）；超過 8 公里不提供配送，新增配送點時直接擋下。距離由店員新增配送點時手動填寫。
- 截單時未達門檻：自動改為門市自取並通知會員；自取時段由「健康餐設定」的「中午自取時段」「晚上自取時段」決定（預設 11:30-13:30、17:30-19:30，待確認）。
- 配送點被停用：該點已有預約者自動改自取並通知。
- 預約頁顯示「預計送達時段」（區間，非保證時間），例如「預計 11:45–12:30 送達（依路況調整，非保證時間）」；此說明也寫進會員條款。
- 時段由「健康餐設定」的「中午預計送達時段」「晚上預計送達時段」決定（各配送點統一，需要時再於「配送點」加欄位）；留白時只顯示「中午配送」「晚上配送」。
- 「延誤判定分鐘」：超過預計時段結束幾分鐘才算店家延誤、可申請補償；留白＝由店員判斷。

### 推薦獎勵
- 推薦人超過每月 10 人上限：推薦紀錄記為「超過上限」，不順延到下個月、不補發；新會員的折扣照給。
- 新會員「取餐滿 3 餐」只計狀態為「已取餐」的（作廢、店家補償不計）；配送的餐由店員標記「已取餐」後才計。
- 新會員未滿 3 餐就取消訂閱：推薦紀錄維持「等待中」直到取消，之後改為「已取消」，不發獎勵；新會員已拿的折扣不收回。
- 推薦碼：6 碼英數字，排除易混淆字元（0／O、1／I），會員中心可一鍵複製。

### 餐數與續訂
- 預約時就預留 1 餐（剩餘餐數減 1）；截單前取消或改期加回 1；截單後（已鎖定）、已取餐、未取餐作廢維持已扣；店家補償加回 1；剩餘餐數為 0 不能再預約。
- 一期 30 天含開始當天（例：11/13 確認收款，到期日 12/12，到期日當天仍可取餐）。
- 續訂：新一期開始日＝續訂的收款確認日；新剩餘餐數＝新方案餐數＋舊期剩餘餐數；舊期標為「已續訂」；已預約的未來餐自動改掛新一期；暫停次數重新計算。
- 續訂時，把「還沒預約」的餐的整期升級差額退回錢包（類型「退款轉入」，可退現金）；例：剩 8 餐已升級雞腿排、已預約 3 餐，退 5×10＝50 元。

## 技術方向（已提出，待負責人確認）
- 【負責人 10/22 指示】資料庫之後會改為 SQL，所以所有後台一律以「直接在後台修改」為主：任何資料（品項、價格、規則、蔬菜、配送點、會員、管理員…）都要能在後台新增、修改、刪除，不再要求人員打開試算表手動改。

  - 現有尚未做到的地方（之後階段補齊）：「配送點」「管理員」「店家」以外的健康餐表格在後台尚無維護畫面；「健康餐設定」目前只能改值，不能新增設定項目（設定項目由程式定義）。
